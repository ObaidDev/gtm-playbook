# The landing page build is guided by criteria, not a vendor

Skills distill only what the Sources say (ADR-0001), and the Sources say what a landing page asks for but nothing about how to build or host one. Left there, a Founder holds a Markdown file and no page for the posts to link to. So `landing-page` makes one scoped exception: after writing the page, it offers to guide the build in a tool the Founder chooses. It gives criteria rather than a vendor (a free plan; hosts the page; asks the Lead stage question with fixed answers; emails the Lead magnet automatically; stores each lead with their answer; an official MCP server preferred), and names HubSpot and MailerLite only as examples that may go out of date. When the tool's MCP server is connected, the agent does what it allows, each action approved by the Founder; otherwise the Founder builds by hand with guidance. We chose MCP over a CLI because none of the all-in-one tools exposes page creation through a CLI, and the guided build over generating static HTML because a static page leaves the Founder to wire up lead storage and Lead magnet delivery. The plugin bundles no MCP configuration, so no Founder is asked to authenticate with a vendor they do not use. The build writes nothing in `gtm/`: the tool and the page's URL are not GTM state. This exception covers `landing-page` only; other skills still add nothing the Sources do not say without asking.
